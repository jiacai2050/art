# ART 线程调度与优先级体系深度总结

本文总结了 ART 运行时中关于线程调度策略、优先级维度及其映射机制的核心设计。

## 1. 调度策略与优先级体系 (Scheduling Policies & Priorities)

在 Linux/Android 中，调度策略决定了内核如何分配 CPU 时间，而优先级则是该策略下的权重参数。

### 1.1 SCHED_OTHER (标准分时策略)
这是 Android 应用线程最常见的默认模式（在现代 Linux 内核中也称为 SCHED_NORMAL），绝大多数从 Zygote fork 出来的线程都运行在此策略下。

*   **工作原理**: 
    *   **完全公平调度 (CFS)**: 目标是确保所有任务公平共享 CPU，避免饥饿。
    *   **动态分时**: 内核根据负载调整执行顺序和时长。
    *   **静态优先级固定为 0**: 始终低于实时策略。
*   **关联的优先级维度**:
    *   **Java Priority (1-10)**: 开发者在 Java 层设置的值。
    *   **Linux Niceness (-20 到 19)**: Java 优先级映射后的底层值。值越小，获得的 CPU 份额越多。
*   **ART 实践**:
    *   **应用线程**: 默认继承自 Zygote，通过 Niceness 进行微调。
    *   **内部线程**: GC 和 JIT 线程通常被赋予极高的 Niceness 值（如 10 或 19），以降低对前台的影响。

### 1.2 SCHED_FIFO (实时抢占策略)
用于对延迟极其敏感的关键任务，优先级高于所有 `SCHED_OTHER` 线程。

*   **工作原理**:
    *   **绝对抢占**: 高优先级实时线程会立即抢占低优先级线程，直到它主动放弃 CPU 或被更高优先级线程抢占。
*   **关联的优先级维度**:
    *   **RT Priority (1-99)**: 数值越大，优先级越高。
*   **ART 中的例外**:
    *   **系统提升**: RenderThread (渲染线程) 和 AudioThreads (音频线程) 经常被系统框架动态提升至此策略。
*   **⚠️ 安全准则 (Critical Warning)**:
    *   **严禁无限自旋**: 在实时线程中，禁止使用纯消耗 CPU 的自旋等待。如果实时线程在等待一个普通线程持有的锁，而它又不进入睡眠，普通线程将永远无法运行，导致**系统永久死锁**。

### 1.3 其他辅助策略
*   **SCHED_BATCH**: 用于非交互式的后台批处理任务。
*   **SCHED_IDLE**: 极低优先级，仅在 CPU 完全闲置时运行。

## 2. 核心映射与缓存机制

*   **映射机制**: ART 通过 `libartpalette` 将 Java 的 1-10 优先级映射为 Niceness。这种映射是不透明的，取决于具体平台的实现。
*   **缓存机制**: 
    *   `Thread.getPriority()` 依赖于缓存的 Niceness 值。
    *   **更新约束**: 仅通过 `Thread.setPriority()` 或 `android.os.Process.setThreadPriority(int)` 修改时，缓存才会更新。直接使用底层系统调用（如针对特定 TID 修改）会导致缓存失效。

## 3. 优先级反转与 ART 的干预逻辑

**优先级反转**（高优先级等待低优先级持有的锁）是 ART 面临的主要调度挑战。

### 3.1 手动优先级提升
在无法大规模启用硬件级 PI Futex 的情况下，ART 采用了手动干预：
1.  **检测**: 检查持有关键锁的线程 Niceness 是否大于 0。
2.  **提升**: 临时将该线程 Niceness 降至 0（提升至正常优先级），加速临界区代码执行。
3.  **恢复**: 操作完成后恢复原值。

### 3.2 为什么不默认使用 PI Futex？
*   **内核支持**: Linux 6.12 之后才对非实时线程提供较好支持。
*   **性能**: PI 机制维护继承链的开销巨大。
*   **可见性**: Java 的 `park/unpark` 机制对内核不可见，无法自动构建继承关系。

## 4. 最佳实践建议

1.  **使用标准 API**: 优先通过 `Thread.setPriority()` 设置优先级，以保持运行时缓存一致。
2.  **缩短持锁时间**: 这是缓解优先级反转最有效的手段。
3.  **避免在实时线程中自旋**: 实时线程必须使用能够让出 CPU 的同步原语（如 Mutex, `Object.wait()`）。
4.  **谨慎使用 JNI 修改**: 如果在 Native 层修改了优先级，务必在返回 Java 前恢复。
